## Smallest usable transport

`tools/render_jobs.py` uses a private local spool with four commands. Use an absolute spool path. Media checks use `ffprobe` when installed, or the bundled macOS AVFoundation probe compiled by Apple `swiftc`; the latter avoids a Homebrew dependency.

```sh
python3 tools/render_jobs.py --root /private/job-spool submit /private/incoming/narration.mp3
python3 tools/render_jobs.py --root /private/job-spool status JOB_ID
python3 tools/render_jobs.py --root /private/job-spool run JOB_ID
python3 tools/render_jobs.py --root /private/job-spool artifact JOB_ID /private/returned/render.mp4
```

Without an administrator adapter, `run` changes queued to blocked; no Moho mutation occurs. When verified, supply `run JOB_ID --adapter /private/config/adapter.json`. That configuration is a host-owned JSON argv array, never uploaded job content. The trusted adapter receives the job directory as its last argument. No arbitrary URL fetch, incoming shell command, automatic paid service or render retry is supported.

State: queued → running → review_required or failed; missing adapter → blocked. Jobs cannot be replayed. New attempts get a new ID, preserving previous output. One worker lock serializes all jobs; after a worker interruption, use process and Moho IPC status commands to verify termination before clearing a stale lock. Never automatically retry an uncertain native write. Initial limits: 25 MiB MP3, 60 seconds input, 30 minute adapter timeout, 64 MiB output (keeps MCP resource reads bounded). No truncation, audio stretching or automatic portrait second render. Under 30 seconds is explicitly diagnostic. There is no dedup/cache claim; integrate existing content-hash stage caches in the adapter.
