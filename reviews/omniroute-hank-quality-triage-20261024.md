## Failure taxonomy: what can actually be distinguished

| Category | Public source evidence | Safe interpretation / acceptance boundary |
| --- | --- | --- |
| **Reasoning-only or empty visible answer** | `omniroute_reasoning_admission.extract_review_text` rejects blank `message.content` as `empty_visible_output`; if `finish_reason=length`, content is blank and *comparable* usage says all completion tokens were reasoning, it raises `reasoning_budget_exhausted`. | Do **not** infer reasoning-only exhaustion when usage is absent or counters are incomparable. The branch explicitly discards inconsistent reasoning-token counts instead of trusting them. An HTTP 200 alone is not a usable draft. |
| **`finish_reason=length`** | `extract_review_text` refuses truncated answers with `incomplete_length_stop`, regardless of whether some visible text exists. `http_completion` maps this to `GatewayTruncatedAnswer`. | No auto-approval or replay. Historical 2400-token receipts and newer 4096-token receipts have distinct near-cap review thresholds in `omniroute_draft_review.py`; a near-cap warning is *not* proof of truncation. |
| **Admission / malformed output** | `extract_review_text` refuses unknown finish reasons, unexpected choice/usage shapes and overlong answers. `prepare_request` separately requires explicitly verified-free routing and supported reasoning-off metadata; it must not be assumed to guard every caller merely because the helper exists. | Preserve the stable error code and never echo raw provider text. Fail closed on uncertain billing/capability. |
| **Public-source overflow or excerpt loss** | `omniroute_workpack_runner.load_packet` enforces per-file bounds and `MAX_INPUT=28000`; approved packets may use 9,000/11,000/14,500-character deterministic excerpts with full-file hashes, included/omitted counts and warnings. Other packets refuse combined overflow. | A failure *before receipt reservation* is not a model response failure. An excerpted answer cannot claim unseen portions were inspected. Source budget is recorded in provenance for review. |
| **Unsupported execution / deployment claims** | `omniroute_draft_review.check_receipt` flags certain first-person execution claims as `execution_claim_needs_review`. `walter_draft_actionability.py` in PR #145 is an independent proposed actionability gate. | Heuristic checks cannot verify that a Mac, Final Cut, GitHub CI, or model ran. Human review remains mandatory, including claims outside the regex. |
| **Stale / placeholder report date** | `REPORT_DATE_HEADER` inspects the first 1,800 characters for date headers, placeholder `XX`, and report-year disagreement with `created_at`; it recognizes several Unicode dash variants. | A date *inside the historical evidence body* should not invalidate the report. A matching header year is not proof that all cited facts are current. |
| **Stale public-source identity / incomplete receipt** | `inspect` recomputes packet and source hashes (including excerpt budget); `check_receipt` distinguishes `stale_source`, `reserved_no_retry`, and `needs_review_no_auto_retry`. | Do not replay a reserved, interrupted, or failed job ID; do not count `draft_completed_needs_review` as accepted output. |

## One bounded, independently testable improvement (proposal only)

**Gap:** `omniroute_workpack_runner.run_packet` writes a fixed allowlisted `admission_code` into some `needs_review_no_auto_retry` receipts (runner lines ~450–456). `omniroute_draft_review.check_receipt` validates that field against `SAFE_ADMISSION_CODES` (reviewer lines ~143–147) but **always returns only** `['inference_failure_no_retry']` for that state (line ~154). `inspect` publishes those generic reasons (lines ~216–219). Therefore a private operator's content-free review summary cannot distinguish an admitted `incomplete_length_stop` from an admitted `empty_visible_output`, even though a safe code was already validated and stored. This is a **source-confirmed observability limitation**, not a claim that either happened on the Mac.

**Smallest proposed change:** On `needs_review_no_auto_retry`, append `'admission_' + obj['admission_code']` to the existing fixed `reasons` array **only after** the current allowlist validation; retain `failed_needs_review`, `response_present=False`, `approval_granted=False`, no-retry behavior and no raw `error_class`, provider body, model answer, credential, or private path. For old receipts without `admission_code`, preserve the generic reason. This change belongs to the existing draft-review owner/PR branch, **not** to this documentation-only claim. Coordinate before implementation; PR #137's current owner also controls this code.

**Focused negative tests (not run):** In `tests/test_omniroute_draft_review.py`, construct synthetic failed receipts with each approved admission code and assert exactly one allowlisted extra reason, unchanged failed/no-retry verdict, no answer exposure; assert absent code preserves the old reason; assert arbitrary string, credential-looking value, wrong type, or extra fields returns `invalid_receipt` without reflection; assert success receipts cannot inject `admission_code`. Run offline Python 3.9 and 3.11 tests and compare the resulting branch's CI checks. **Do not use live inference or private Mac data for this test.**
