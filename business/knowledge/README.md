# Rovor knowledge pack

Snapshot reviewed: 2026-10-21. Source revision: `2d1299fc4d033b23d3fea29f000a305030e9b5f5`.
This is a compact retrieval index for ChatGPT sessions, not another task queue or a claim that all
business details are known. Read current root AGENTS.md and WORK.md before taking action.

## Use in a new session

1. Read facts.json. Select only facts relevant to the requested deliverable.
2. Open their source paths at the recorded revision for provenance; refresh current source before
   relying on mutable status. Check live coordination/tasks.json for ownership and dependencies.
3. Separate repository policy, business description, future goals and unknowns in the response.
4. Use the existing website delivery playbook and templates for delivery work.
5. If a needed fact is missing, record the gap and continue independent work. Ask only when the
   missing fact blocks the selected deliverable. Do not fill a gap with an old chat assumption.

[facts.json](facts.json) contains source paths, section anchors and explicit limits.
[decisions-and-gaps.md](decisions-and-gaps.md) gives decisions and resolution paths.
These files contain no client records, credentials, transcripts or copied private media.

## Quick answers supported by the sources

- **What is Rovor?** Rovor Digital helps businesses with websites, branding, content and connected
  inquiry/customer systems. This describes service areas, not a priced package or a client result.
- **What are we building?** A multi-capability business assistant, ChatGPT-first now; video is one
  capability. Selected local execution and bounded unattended jobs are later stages.
- **What should a session preserve?** Exact existing Rovor branding, approved Evan references,
  original narration and source work. Locate and verify actual source assets before editing.
- **What is a completed job?** Implementation, technical verification, approval, publication and
  delivery are separate states. Cite the evidence for the state being claimed.
- **What can we promise customers?** Only actual agreed scope, price, timing and supported results.
  This pack supplies no standard price, turnaround, testimonial or performance guarantee.

## Source conflict handling

Explicit current user direction takes precedence over historical summaries. For repository direction,
use the current master plan and AGENTS.md; for work ownership use the current canonical queue.
PROJECT-LOOP.md includes an older video-focused snapshot: its preservation rules remain useful,
but its dated task descriptions must not override live queue/PR evidence or the broader master plan.
Likewise, the separately authorized audio import is a scoped exception to the default private-media rule;
it does not authorize unrestricted copying of other client files.

When two source statements conflict, retain both references, identify which date/scope applies,
and resolve the affected fact before making a promise. Do not silently promote a proposal to approval.

## Updating the pack

Claim business/knowledge through the existing queue before changing it. Add or revise the relevant
fact with its exact source revision, classification and limitation. Record superseded decisions with
their replacement reason; do not erase history to hide contradictions. Refresh only affected facts.
An absent fact means "not established here", not "the business does not have it".
