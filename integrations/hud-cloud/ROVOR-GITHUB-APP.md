# ROVOR-owned GitHub App: independent native discovery

This is the first read-only tool gateway in the existing Cloudflare HUD. The existing five-minute native clock uses a one-hour D1 lease and queues only verified, deduplicated numeric GitHub evidence in the existing inbox. It does not infer, modify repositories, approve jobs, or require ChatGPT, the Mac, or scheduled GitHub Actions. Existing STOP and standing authorization must be active. The prior GitHub discovery workflow remains a compatibility fallback until native execution is verified; both share D1 deduplication and a six-record daily cap.

## Owner setup (one time)

Create an organization-owned GitHub App in TeamRovor settings. Disable webhooks for this initial polling implementation. Grant **read** Contents, Issues, Pull requests, Actions (and automatic Metadata read). Install only on TeamRovor/rovor-video-engine. Generate an app private key. Store the App ID, installation ID, and original RSA PEM as production Actions secrets named `ROVOR_GITHUB_APP_ID`, `ROVOR_GITHUB_INSTALLATION_ID`, and `ROVOR_GITHUB_APP_PRIVATE_KEY`. Set production variable `ROVOR_NATIVE_DISCOVERY_ENABLED=true`. Do not put private key material in chat, logs, the repository, or browser code. The existing protected HUD deployment transfers these settings to its existing Worker. The runtime requests a short-lived single-repository read token and rejects extra write permissions. No personal access token is required.

After the real owner review and standing authorization, verify authenticated `GET /api/hud/workforce/native-discovery` shows a native D1 receipt and the existing discovery inbox advances. A configured flag alone is not proof. Only then retire the GitHub Actions discovery schedule with a separate reviewed change. GitHub write tools require a separate bounded policy and are not included in this read-only milestone.

## Optional reviewed draft-patch stage

Only after the read-only installation succeeds, the owner may grant Contents and Pull requests write on the same single repository. Read discovery still requests a downscoped read-only token; patch operations request only Contents/Pull requests write and automatic Metadata read. Set `ROVOR_GITHUB_PATCH_ENABLED=true` and `ROVOR_GITHUB_PATCH_PATHS` to a JSON array of exact allowed paths (initial supported roots: architecture/business/design Markdown, the two HUD CSS files, and bounded evan-engine source). All other paths, workflow files and Core are denied. Only a separately authorized, human-PASS'd code_review job containing the exact JSON proposal below is accepted. POST /api/hud/workforce/github-patch with the existing server-side writer credential and {job_id,output_sha256}; the API queues only. The native clock performs a single nonreplayable draft PR attempt while STOP is enabled. No direct merge/deploy. An uncertain attempt blocks subsequent writes; reconcile manually rather than replay.

Proposal format: {"version":1,"base_commit":"40-character reviewed main SHA","title":"Short summary","summary":"Reason and verification","change":{"path":"owner-allowlisted existing path","blob_sha":"40-character reviewed blob SHA","before":"unique exact original text","after":"replacement text"}}.

## Direct private HUD owner control

Set a new random 32–200 character printable, non-whitespace owner secret as `ROVOR_HUD_OWNER_TOKEN` in the protected production environment; it must be distinct from the existing reader and writer keys. The existing deploy transfers it to the Worker as `HUD_OWNER_TOKEN`. Sign in to the same private HUD using this key once per 24-hour owner session. The browser receives a signed, expiring HttpOnly owner cookie, never the raw owner key. Viewing-key login revokes the owner cookie. Once configured, PASS/FAIL requires the separate owner session. The owner desk supports direct seven-day standing authorization and STOP; the source commit comes from the deployed reviewed checkout and the same D1 PASS/STOP/empty-queue guards apply. It can also queue an exact accepted patch with a separate explicit confirmation. This does not immediately call a provider or write to GitHub. The protected GitHub workflows remain fallback, not a runtime dependency.
