# ROVOR software specialist — research before automation

This is an instruction skill, **not a live, scheduled agent, installer, web crawler or permission grant**. Reuse it for Jane/Final Cut Pro, Jesse/Moho, Gale/Blender and later ROVOR specialists. Walter owns orchestration through the existing AGENTS.md/WORK.md queue; never set up a new claims ledger.

## Research contract for unfamiliar software

1. **Define the business outcome**: what concrete ROVOR YouTube/reels/client deliverable improves? Which input assets, duration, formats and review steps?
2. **Verify what's installed** on the actual target OS only if host execution is available. Record product/version, CPU architecture, toolchain, licenses and safe test folder. Otherwise mark host facts **unknown**.
3. **Start with primary sources**: official product manual, developer APIs, supported interchange formats, export policies and licensing. Date each claim and URL. Then inspect third-party implementation repositories and license, release/version, source, declared dependencies, security model, write scopes and regression tests.
4. **Compare control surfaces**: documented native API/interchange; supported extensions/MCP; CLI; accessibility/GUI automation; undocumented binary patch. Prefer official, testable, non-destructive routes. Explain read vs write vs render/export separately.
5. **Build a one-page evidence ledger**: claim, source URL, date/version observed, confidence (verified source / maintainer claim / hypothesis), test to disprove, and result. Don't repeat unverified claims as knowledge.
6. **Propose the minimum viable connection**: project-scoped, localhost-only where needed, least privileges, pinned third-party version, disposable paths and project, rollback, no secrets in repo, no implicit paid providers. Request approval for software installation, wider OS privileges or actions beyond the authorized workspace.
7. **Test in phases**: static config → tool discovery → one read-only invocation → reversible write on a disposable project → exported artifact inspection. Record actual exact commands, output files and failure screenshots/logs without private data. A config entry or open socket is NOT a successful handshake.
8. **Deliver practical learning**: workflow instructions, mappings from ROVOR inputs to finished YouTube/reels outputs, skill gap analysis, automation boundaries, first reviewed pilot video and source-preserving reusable template.
9. **Publish an evidence handoff** using GitHub task id, branch/commit/PR, tested machine, actual permissions, blockers, specific next action. Do not silently edit someone else's claimed work.
10. **Continue only when explicitly invoked or under a verified scheduler**. An instruction/role does not wake a sleeping Mac, bypass quotas, execute a local app from a cloud chat or work uninterrupted in the background.

## Universal disqualifiers

Reject any integration that requires unreviewed root/sudo, disables Apple security, patches a licensed application's executable, publicly exposes localhost, stores API keys in GitHub, blindly installs arbitrary scripts, changes original media, or posts/publishes without authorization. Prefer read-only testing and manual approval over speed.

## Quality gates

**Research complete** = sources and dated decisions recorded. **Configured** = valid config present. **Connected** = real host tool handshake with observed app/version. **Capable** = repeatable disposable edit/render. **Production-ready** = original-audio/source-fidelity technical QA, meaningful creative review, stable rollback, release authorization. Keep these states separate.

For Final Cut Pro, read `integrations/final-cut-pro/README.md` and `integrations/final-cut-pro/RESEARCH-PACKET.md`. The approved target is YouTube 1920×1080/60fps and Reels 1080×1920/60fps when source and workflow support it; 30 seconds minimum for final review previews. Shorter shots are diagnostic only.
